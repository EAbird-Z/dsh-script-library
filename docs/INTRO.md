# 脚本库 — 介绍

## 一句话

给 DeepSeek Harness 加一块「我做过什么工具」的看板：点一下扫出新写的脚本，填一句话登记进清单，之后任何工作区都能查到、能直接调。

## 问题

用 agent 干活的人都会遇到这个循环：

```
在新目录里做事
  → 需要一个脚本
  → 忘了三个月前写过
  → 从头再写一个
  → 又忘了登记
```

笔记软件解决不了，因为**agent 不会去翻你的笔记**。文档也解决不了，因为换个工作区它就消失了。

要真正解决，得让"清单"出现在每次会话开场就自动加载的地方 —— 在 DSH 里那是 skill 的 catalog 和 tool 列表。

## 做法

三件东西，各管一段：

| | 存在 | 作用 |
|---|---|---|
| **清单** `registry.json` | 本机一份 | 每条 = id + 一句话 + 跑在哪个目录 + 怎么起 + 依赖 |
| **扫描器** `scan.py` | 包内 | 只读。比对基线，报"上次之后新出现的文件" |
| **面板** | 侧边栏 | 清册（带现场体检）+ 待登记（勾选 + 填一句话） |

关键在于**两层记录分开**：

- `.seen.json` 机器写的 —— 保证每次只报新增，不会把 183 个文件倒给你
- `registry.json` 人写的 —— 保证"查到就知道它是干嘛的、还能不能跑"

只有前者，你不知道那文件有什么用；只有后者，每次都得从头分类。

## 三个刻意的"不做"

- **不自动登记。** 清单的价值是策展。把跑过一次的临时脚本收进来，清单就废了。
- **不自动编解释。** 「干什么的」必须自己填。这一句是以后能不能搜到的唯一依据，猜不出来。
- **不为了检查去跑脚本。** 体检只查路径和文件存在性。

## 边界

- 只读扫描，除了 store 里那两个 JSON，不写任何东西
- 默认只扫已注册的工作区；其他目录写进 `roots.json`
- 本机绝对路径，不跨机器
- 扫描器零第三方依赖，`python3` 就能跑

## 适合谁

- 用 agent 长时间做项目，脚本越攒越多的人
- 同时维护好几个工作区，分不清哪个脚本是最终版的人
- 想让人和 agent 共用同一份"工具箱清单"的团队
