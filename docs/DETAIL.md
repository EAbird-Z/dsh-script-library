# 脚本库

维护一份**跨工作区的可调用清单**，并且在「登记」这一步给你一个按钮。

## 它解决什么

不同工作区里反复写脚本，过一阵就忘了写过什么，又从头写一遍。单靠 Markdown 笔记，换个目录就没人知道它存在；单靠记忆，三个月归零。

这个插件把「发现」变成一次点击，把「清单」放成一个所有工作区共用的 JSON。

## 两个标签

**清册** —— 所有已登记条目。每条显示 id、类型、一句话、跑在哪个目录、怎么起、注意什么，右侧是现场体检：

- 目录还在不在
- 入口文件还在不在
- 声明过的依赖还在不在

坏了就标红并写清原因（比如外接盘没挂会直接写「目录不存在」）。顶部可按 id、名字、标签、路径筛选。

**待登记** —— 点「扫一遍」，列出**上次之后新出现、且清单里还没有**的脚本。勾选、填一句「干什么的」、登记。登记后自动更新基线，下次不再出现。

## 数据在哪

默认 `~/.dsh/script-library/`：

| 文件 | 作用 |
|---|---|
| `registry.json` | 唯一真相源，所有可调用条目 |
| `.seen.json` | 扫描基线 |
| `roots.json` | 可选，额外的扫描根 |
| `INDEX.md` | 可选，给人读的账本（插件不写） |

如果机器上已有 `~/.dsh/skills/script-index/registry.json`，插件会**采纳**它作为 store，不另起一份。

## 边界

- **只读扫描**：不移动、不修改、不删除被扫的文件；唯一写入的是 store 里的两个 JSON。
- **不自动登记**：清单的价值是策展，不收跑过一次的临时脚本。
- **不做代码搜索**：它管「有哪些工具、怎么调」，不管「这段代码在哪」。
- **体检不执行**：只查路径和文件存在性，不为验证去跑你的脚本。
- **不跨机器**：条目里是本机绝对路径。

## 扫描根

默认只扫**已注册的工作区**。不在工作区里的目录写进 `roots.json`：

```json
{ "roots": [ { "path": "~/Downloads/素材", "depth": 2 } ] }
```

`depth` 默认 2（工程根 + 一级子目录）。再深容易把第三方项目内部结构一起卷进来。
